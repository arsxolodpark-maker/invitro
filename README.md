# ПРИИЗ INVITRO - UX Prototype v0.7 DEMO

ПРИИЗ - **Портал для Регистрации Инцидентов в Интеграциях Здравоохранения**.

Рабочий UX-прототип модуля «Инциденты / ПРИИЗ» внутри целевого единого фронта ДКП. Основа v0.7 - аналитика «Описание функциональности Системы регистрации обращений v9» и комментарии владельца продукта.

## Что показывает v0.7

- внешний контур `Инициатор`: активация по приглашению ДКП, вход, свои обращения, статусы и комментарии;
- внутренний контур `ДКП`: создание и сопровождение обращений, управление внешними инициаторами в целевой модели;
- `Инженер ГСТИ`: обработка обращения преимущественно в существующем контуре `1C:ITILIUM`, без обязательного двойного ведения в ПРИИЗ;
- `Администратор`: пользователи, роли и чаты `Express`;
- `Project`: дополнительный внутренний аналитический view прототипа, не утвержденная промышленная роль v9;
- пользовательская статусная модель из v9: `Новое / В работе / Отложено / Ожидает ответа / Ожидает согласования / Выполнено / Закрыт`;
- подтвержденная роль `1C:ITILIUM`: создание и получение обращений, получение статусов, работа с организациями и инициаторами;
- `Express` как канал нотификаций;
- База знаний для проектной документации, runbook и инструкций;
- единственный рабочий DEMO-сценарий пока `INC-02 Не получен результат`.

## Регистрация пользователя

В аналитике v9 есть конфликт требований: общие ФТ допускают самостоятельную регистрацию, а детальный UC описывает сценарий `ДКП создает пользователя -> пользователь получает ссылку -> активирует аккаунт`.

В v0.7 реализован второй, более детально описанный сценарий. Self-registration помечается как `TBD` до подтверждения.

## 1C:ITILIUM

Подтверждено аналитикой v9:

- создание обращения;
- получение обращений по параметрам;
- получение статуса обращения;
- `CreateOrganization`;
- `CheckOrganization`;
- `UpdateOrganization`;
- `RegisterUser` для инициатора.

Точный production-контракт двусторонней синхронизации комментариев, вложений, исполнителей и разрешения конфликтов пока `TBD`.

## Express

Аналитика v9 требует интеграцию с Express для нотификаций и возможность администратора добавлять, изменять и удалять чаты. В прототипе это показано как DEMO-flow без реального API.

## Связь с GOVIN

GOVIN-303 «Проверка направления» и ПРИИЗ - отдельные продуктовые модули единого фронта ДКП.

Целевой переход: `GOVIN -> найден диагностический контекст -> Создать обращение в ПРИИЗ`.

GOVIN отвечает на вопрос «что произошло с направлением?», ПРИИЗ - «как зарегистрировать проблему, кто ее решает и где коммуникация?».

## Что намеренно не считаем подтвержденным

- финальный каталог типов обращений - ждем фактическую статистику;
- реальные baseline-метрики и экономика - ждем фактические данные;
- промышленная роль Project в RBAC;
- self-registration;
- точный контракт синхронизации комментариев с 1C:ITILIUM;
- реальные источники и права для Базы знаний / AI-поиска.

## Безопасность DEMO

Все клиенты, ИНЗ, номера тикетов, метрики и технические результаты в публичном прототипе являются демонстрационными. Реальные внутренние URL, секреты и персональные/медицинские данные не используются.
