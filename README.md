# ПРИИЗ INVITRO - UX Prototype v0.3 DEMO

Демонстрационный пользовательский прототип для регистрации и сопровождения инцидентов интеграций.

> Важно: точная расшифровка сокращения «ПРИИЗ» пока не подтверждена владельцем продукта, поэтому в проекте оно используется как рабочее название без расшифровки.

## Зачем этот прототип

Показать целевой пользовательский сценарий на примере INC-02 «Не получен результат»:

- выбрать тип проблемы;
- собрать обязательный контекст с первого раза;
- выполнить демонстрационный pre-check;
- создать единое обращение с одним номером и историей;
- показать статус и безопасный результат диагностики;
- разделить пользовательский слой ПРИИЗ и внутренний инженерный контур;
- заложить продуктовые метрики для будущего AS-IS / TO-BE и unit economics.

## Что уже известно про AS-IS

Проект не предполагает создание корпоративного контура INVITRO с нуля. По текущим вводным уже существуют:

- интеграционная платформа;
- домен «Сервис»;
- внутренние механизмы Service Desk / 1С;
- часть мониторинга;
- тестовый стенд, который требует дальнейшего уточнения по возможностям.

Архитектурный принцип: **reuse / integrate first**. Новую разработку предлагаем только после подтверждения реального gap.

## Что демонстрирует приложение

1. Главная страница и список обращений.
2. Выбор типа инцидента.
3. Динамическая форма INC-02 «Не получен результат».
4. Предварительная проверка на mock-данных.
5. Карточка инцидента с одной историей коммуникации.
6. Роли ДКП, Manager, Project, Product и Support.
7. Product / Manager аналитику на DEMO DATA.
8. Безопасный demo-переход во внутреннюю Integration Console без реальных API, логов и управляющих операций.

## Безопасность демо

- используются только вымышленные данные;
- реальные медицинские и персональные данные не используются;
- реальные API INVITRO, 1С и Service Desk не подключены;
- реальные внутренние адреса, протоколы, журналы и секреты не публикуются;
- все технические интеграции остаются TBD до подтверждения архитектуры и требований ИБ.

## Локальный запуск

```bash
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
npm run preview
```

Результат сборки создается в `dist/`.

## GitHub Pages

Публичная demo-версия:

`https://arsxolodpark-maker.github.io/invitro/`

Публикация выполняется workflow:

`.github/workflows/deploy.yml`

Workflow при push в `main`:

1. устанавливает зависимости;
2. выполняет `npm run build`;
3. загружает `dist/` как GitHub Pages artifact;
4. публикует artifact в environment `github-pages`.

В настройках репозитория используется:

**Settings -> Pages -> Build and deployment -> Source -> GitHub Actions**.
