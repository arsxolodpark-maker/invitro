# GOVIN-303 · DEMO v0.6.0 — Release Gate

Дата фиксации: 27.08.2026

Статус: **DEMO READY**

## 1. Что изменилось относительно v0.5.4

Главная UX-архитектура переведена в outcome-first режим:

**Поиск → Итог проверки → Что делать сейчас → одно главное действие → детали по запросу → маппинг отдельным уровнем.**

Технические данные направления, этапы процесса и таблица маппинга больше не конкурируют с главным пользовательским выводом.

## 2. Карточки S1–S5

- **S1 — успешный путь:** сначала видно «С направлением всё в порядке» и «Ничего делать не нужно»; основное действие — проверить другое направление.
- **S2 — нет маппинга услуги:** сразу виден проблемный этап «Получение услуг / создание направления», конкретное действие до чекина и CTA «Создать обращение в ПРИИЗ».
- **S3 — нечекин:** сразу видны причина, этап «Чекин» и действие «исправить маппинг услуги + направить заявку на ручное лабораторное исполнение».
- **S4 — ошибка доставки:** сразу видны этап «Доставка результатов», отсутствие маппинга теста и действие по исправлению/повторной отправке.
- **S5 — направление не найдено:** неизвестные клиент, ЛПУ и ИНЗ не подставляются; пользователь получает понятную проверку номера/интеграции и путь эскалации.

## 3. Progressive disclosure

Подтверждено:

- детали проверки скрыты по умолчанию;
- S1–S4 раскрывают данные направления и три этапа только по кнопке пользователя;
- при раскрытии проблемного сценария автоматически открывается проблемный этап;
- таблица маппинга находится ещё на один уровень глубже и скрыта по умолчанию;
- для S5 технические детали отсутствующего направления не показываются.

## 4. GOVIN → ПРИИЗ

Подтвержден перенос известного контекста для проблемных сценариев:

- S2 — ИНЗ может отсутствовать и остаётся пустым;
- S3 — передаётся известный ИНЗ;
- S4 — передаётся известный ИНЗ и контекст ошибки доставки;
- S5 — клиент, код клиента, ЛПУ и ИНЗ остаются пустыми; интеграция и введённый идентификатор сохраняются.

Неизвестные данные не генерируются.

## 6. Ручной визуальный QA

Повторно просмотрены outcome-карточки S1–S5 и раскрытые карточки S1–S4 на desktop и mobile.

Проверено:

- пользовательский итог визуально доминирует над техническими деталями;
- «Что делать сейчас» читается до перехода к деталям;
- основная CTA визуально выделена;
- вторичное действие «Показать детали проверки» не конкурирует с основной CTA;
- проблемный этап после раскрытия виден без поиска по экрану;
- маппинг не создаёт шум до явного запроса;
- длинные карточки на mobile складываются вертикально и остаются читаемыми.
