# GOVIN-303 — UX Flow v0.6.0

Статус: рабочая спецификация DEMO.

## Главный принцип

После поиска менеджер ДКП не должен разбирать технический экран, чтобы понять, что делать.

Основной flow:

**Поиск → Итог проверки → Что делать сейчас → одно главное действие → детали по запросу → маппинг ещё глубже.**

Детали направления, этапы и таблица маппинга не показываются до тех пор, пока пользователь сам не нажмёт «Показать детали проверки» / «Показать маппинг».

## Первый экран

Показываем только:
- Интеграция.
- Номер направления / штрихкод.
- Кнопка «Проверить направление».

После выбора интеграции фокус переходит в поле номера. При пустом поле после нажатия показывается конкретная ошибка и фокус переводится в нужное поле.

## Карточки S1–S5

| Сценарий | Что видит менеджер первым | Что делать сейчас | Главное действие | Детали |
| --- | --- | --- | --- | --- |
| S1 — успешный путь | «С направлением всё в порядке» | Ничего делать не нужно | «Проверить другое направление» | Опционально: этапы 1–3, тесты/результаты, маппинг |
| S2 — нет маппинга услуги | «Нет маппинга услуги» + проблемный этап «Получение услуг / создание направления» | Исправить маппинг до чекина и повторно проверить сопоставление | «Создать обращение в ПРИИЗ» | Этап 1 раскрывается первым; маппинг услуги доступен отдельно |
| S3 — нечекин | «Нечекин / нет маппинга услуги» + проблемный этап «Чекин» | Исправить маппинг услуги и направить заявку на ручное лабораторное исполнение | «Создать обращение в ПРИИЗ» | Этап 2 раскрывается первым; биоматериал в логике отсутствует |
| S4 — ошибка доставки | «Ошибка доставки / нет маппинга теста» + проблемный этап «Доставка результатов» | Исправить маппинг теста, загрузить корректный маппинг и повторно инициировать отправку | «Создать обращение в ПРИИЗ» | Этап 3 раскрывается первым; видно, что доставка отменена; маппинг теста отдельно |
| S5 — направление не найдено | «Направление не найдено» | Проверить номер и интеграцию; если данные верны — эскалировать | «Создать обращение в ПРИИЗ» + вторичное «Проверить другое направление» | Технических деталей направления нет, неизвестные клиент/ЛПУ/ИНЗ не выдумываются |

## Иерархия результата

1. **Итог проверки** — самый заметный текст.
2. **Проблемный этап** — если есть ошибка.
3. **Что делать сейчас** — крупный рабочий текст.
4. **Главная CTA** — одно основное действие.
5. **Показать детали проверки** — вторичный уровень.
6. В деталях: данные направления + три этапа.
7. **Показать маппинг** — третий уровень технической детализации.

## GOVIN → ПРИИЗ

Для S2/S3/S4/S5 GOVIN передаёт только известный контекст.

- S2: INZ может отсутствовать и остаётся пустым.
- S3/S4: передаётся известный INZ.
- S5: клиент, код клиента, ЛПУ и INZ остаются пустыми; неизвестные данные не подставляются.

## QA Gate v0.6.0

Обязательно проверяются:
- S1–S5 outcome на desktop и mobile.
- S1–S4 раскрытые details на desktop и mobile.
- отсутствие горизонтального overflow.
- длинные строки не выходят за границы своих блоков.
- маппинг скрыт по умолчанию.
- переход GOVIN → ПРИИЗ для S2/S3/S4/S5.
