# GOVIN-303 — UX v0.5.9

## Статус

Утверждённый UX-концепт первого экрана после анализа пользовательской понятности и обратной связи по v0.5.6–v0.5.8.

## Ключевое решение

До выполнения поиска GOVIN не показывает бизнес-процесс как стрелочную цепочку и не имитирует wizard 1–2–3.

Первый экран содержит одно рабочее действие:

**Интеграция + Номер направления / штрихкод + Проверить направление**

После выбора интеграции фокус переводится в поле номера. При попытке проверки с незаполненными данными GOVIN фокусирует конкретное обязательное поле и показывает короткую валидацию.

## После поиска

Только после получения результата появляются три бизнес-этапа:

1. Получение услуг / создание направления — контроль маппинга услуг.
2. Чекин — повторный контроль маппинга услуг.
3. Доставка результатов — контроль маппинга тестов.

Этапы являются реальными кликабельными элементами. В свёрнутом состоянии показываются номер, название, статус и тип контроля. По клику раскрывается:

**Что проверяем → Что увидели → Действие ДКП**

Одновременно раскрывается максимум один этап.

## Что не менялось

- бизнес-правила S1–S5;
- service mapping на этапах создания и чекина;
- test mapping на доставке;
- при отсутствии маппинга теста доставка отменена целиком в DEMO;
- S3 не содержит маппинг биоматериала;
- GOVIN → ПРИИЗ переносит известный контекст;
- для S2/S5 ИНЗ не является обязательным GOVIN-контекстом;
- реальные production API и маршруты остаются Technical Discovery / REG-TBD.

## DEMO-элементы

DEMO-сценарии не конкурируют с основной рабочей формой. На desktop они находятся на вторичном уровне; на mobile не участвуют в основном пользовательском сценарии. Основной QA проходит через реальный search-flow, а не через DEMO-чипы.

## Acceptance criteria

- на первом экране отсутствует декоративная строка `Получение услуг → чекин → доставка результатов`;
- на первом экране отсутствуют псевдошаги `1 / 2 / 3`;
- до поиска нет карточек бизнес-этапов;
- видны интеграция, номер/штрихкод и одна CTA `Проверить направление`;
- выбор интеграции переводит фокус в поле номера;
- Enter в поле номера запускает проверку;
- после поиска появляются статус, компактные данные направления и кликабельные бизнес-этапы;
- desktop и mobile используют одну бизнес-логику;
- S1–S5 и GOVIN → ПРИИЗ проходят regression QA.

## Release Gate

Для рабочей React-ветки v0.5.9: TypeScript + production build + desktop/mobile E2E должны быть зелёными до публикации.

Публичная Pages-версия считается DEMO READY только после успешного deploy и live visual QA.
