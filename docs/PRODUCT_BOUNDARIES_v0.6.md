# INVITRO - границы продуктов: единый фронт ДКП, GOVIN и ПРИИЗ

Статус: рабочая фиксация по двум аналитическим документам от 17.08.2026 и комментариям Ирины.

## 1. Единый фронт ДКП

Это общий пользовательский контур для сотрудников ДКП. Он не равен одному конкретному продукту и должен объединять независимые рабочие модули через единый интерфейс.

Целевые модули:
- Проверка направления - GOVIN-303;
- Инциденты - ПРИИЗ;
- ОМС / лимиты;
- Маркетплейс;
- Покрытие;
- Платформа / заявка на интеграцию.

## 2. GOVIN-303 - отдельный продуктовый модуль

Рабочее название в исходном документе: «Система для менеджеров ДКП по проверке статуса направления».

Пользовательская задача: найти внешнее направление по штрихкоду и увидеть его состояние и диагностический контекст.

Подтвержденные данные карточки направления:
- внешний идентификатор;
- дата направления;
- клиент;
- статус;
- список ИНЗ;
- назначенные тесты;
- доставленные тесты;
- ошибки чекина / доставки;
- дата последней доставки.

Подтвержденные сервисы в постановке:
- Нетрика;
- Адыгея;
- Брегис.

Архитектурный паттерн: единый Web UI -> Gateway -> сервис конкретной интеграции.

GOVIN не является ПРИИЗ. Его ответственность - ответить на вопрос «что произошло с направлением и на каком оно этапе?».

## 3. ПРИИЗ - отдельный продуктовый модуль

Подтвержденное название: «Портал для Регистрации Инцидентов в Интеграциях Здравоохранения».

Пользовательская задача: зарегистрировать обращение, сопровождать его, получать статусы и вести коммуникацию по инциденту.

Подтвержденные роли исходного документа:
- Инициатор;
- Менеджер ДКП;
- Инженер ГСТИ;
- Администратор.

Дополнительная роль Project сохранена в UX-прототипе на основании отдельного комментария владельца продукта и должна быть сверена с конечной промышленной RBAC-моделью.

Подтвержденные интеграции:
- 1C:ITILIUM - создание/получение обращений и статусов, регистрация организаций и инициаторов;
- Express - нотификации в чаты.

## 4. Связь GOVIN -> ПРИИЗ

Это связь двух продуктов, а не объединение их бизнес-логики.

Целевой UX-переход:
1. ДКП открывает «Проверку направления».
2. Выбирает интеграцию и вводит штрихкод.
3. GOVIN показывает направление, ИНЗ, тесты, этап и ошибки.
4. Если требуется работа с инцидентом, пользователь нажимает «Создать обращение в ПРИИЗ».
5. Подтвержденный диагностический контекст GOVIN передается в форму ПРИИЗ и не вводится повторно.

Передача данных GOVIN -> ПРИИЗ является целевым продуктовым решением для прототипа. Конкретный промышленный API-контракт между модулями должен быть согласован отдельно.

## 5. Важная граница

GOVIN отвечает: «где направление и что с ним произошло?».

ПРИИЗ отвечает: «как зарегистрировать проблему, кто ее решает, какой статус и где коммуникация?».

Единый фронт ДКП отвечает: «как сотруднику ДКП работать с этими и другими продуктами из одного интерфейса?».
