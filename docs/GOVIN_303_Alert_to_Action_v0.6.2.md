# GOVIN-303 · Alert-to-Action v0.6.2

## Цель

Проверить GOVIN не как отдельный экран, а как рабочий путь менеджера ДКП:

**входящий сигнал → извлечение входных данных → поиск в GOVIN → понятный итог → действие → при необходимости ПРИИЗ**.

## Что подтверждено источниками

### Постановка GOVIN-303

- Пользователь: менеджер ДКП.
- Есть поиск направления по штрихкоду.
- Пользователь вводит штрихкод и запускает поиск.
- Gateway передает `query={barcode}` сервису интеграции.
- В постановке присутствуют интеграции Нетрика, Адыгея, Брегис.

Следствие для прототипа: **подтвержденный поисковый ключ — штрихкод направления**.

### Интервью / рабочие записи

- ДКП получает технические алерты либо жалобы по проблемным направлениям.
- После сигнала менеджеру приходится собирать контекст и выяснять причину.
- При реальной технической проблеме контекст должен переходить в ПРИИЗ / поддержку.

## Минимальный входной контракт для текущего UX

Чтобы менеджер мог без дополнительного расследования перейти в GOVIN, ему нужны:

1. **Интеграция** — Нетрика / Адыгея / Брегис.
2. **Штрихкод направления** — поисковый ключ GOVIN.

Если хотя бы одно из этих полей отсутствует в реальном источнике, нужен отдельный продуктовый сценарий поиска/уточнения. Не подменять его догадкой.

## Целевой пользовательский путь

1. Ирина получает входящий сигнал.
2. Видит/определяет интеграцию и штрихкод.
3. Открывает GOVIN.
4. Переносит интеграцию и штрихкод в поиск.
5. Нажимает **«Проверить направление»**.
6. GOVIN отвечает сначала пользовательским итогом:
   - S1 — все в порядке;
   - S2 — услуга не сопоставлена;
   - S3 — направление не прошло чекин;
   - S4 — результаты не доставлены;
   - S5 — направление не найдено.
7. GOVIN показывает **«Что делать сейчас»**.
8. Пользователь выполняет главное действие.
9. Если нужен технический разбор — GOVIN передает известный контекст в ПРИИЗ.
10. Неизвестные поля не выдумываются.

## Правила UX

- До поиска не показывать результат заранее.
- DEMO-сигнал может только подставить входные данные, но не выполнять поиск автоматически.
- В рабочей форме использовать термин **«Штрихкод направления»**, а не расширять подтвержденный контракт до «номер / штрихкод».
- S5: сначала перепроверка штрихкода и интеграции, потом эскалация.
- Технические детали и маппинг остаются вторым уровнем.
- ПРИИЗ не заменяет GOVIN: переход только когда найдено действие, требующее регистрации/технического разбора.
